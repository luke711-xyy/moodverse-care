## 1. 目标、参考与施工边界

### 1.1 最终体验

用户坐在一座复古飞船驾驶舱中：透过上方大面积玻璃观察实时音乐宇宙，在下方环抱式控制台选择探索方式、记录 Moment、联系朋友。功能入口从独立导航栏和弹窗，变成有明确用途的屏幕、按钮、旋钮和操纵杆。

主要行动链路是：选择探索方式 → 在终端看到结果 → 确认访问 → 穿越星云 → 在舷窗观察对方星球 → 打开终端查看资料或继续探索。

这不是将网站变成一张不可操作的驾驶舱插画，也不是重新引入重型 3D 模型；而是用可交互的代码部件形成有空间感的界面。

## 2. 驾驶舱空间构成

### 2.1 总览布局

```text
┌────────────────── 舷窗 / 实时宇宙 ──────────────────┐
│                                                     │
│       我的星球 / Galaxy / 对方星球                   │
│       鼠标交互、旋转、卫星、实时 dithering            │
│                                                     │
│             星系标识与横向导航轴                    │
├──────╲────────────────────────────────╱─────────────┤
│ 个人终端 ╲  航向表  探索终端  信号表 ╱ 分类与设置区 │
│ 星球/Orbit ╲       撞歌/漫游/瓶      ╱ 旋钮/航行杆  │
│  Moment     ╲______________________╱               │
└─────────────────────────────────────────────────────┘
```

桌面总览的建议比例：舷窗约占画面高度的 75%–80%，控制台约占 20%–25%。比例以两张图的空间关系和实际可点击尺寸共同决定，不为了死守比例把屏幕压到无法使用。

包围感通过以下关系形成：

- 左右翼高于中间控制台，向观众内侧转入；中间较低、较靠前。
- 左右设备具有可见侧壁、屏幕厚边、凹槽、螺钉和短距离硬阴影；中央有前沿与通风槽。
- 使用 CSS 透视与轻度旋转实现 2.5D；起调范围为侧翼向内约 8°–14°，最终用浏览器实测校正。
- 页面整体不倾斜，文字不长期保持大角度斜切；靠近终端后屏幕完全正视，避免看不清和点击坐标偏差。
- 控制台是连续的装置，不是三张等宽卡片。仪表和硬件充当区域间的连接，而非新增功能卡片。

### 2.2 区域职责

| 物理区域 | 常驻内容 | 点击后 |
| --- | --- | --- |
| 大舷窗 | 当前外部场景 | 保留当前场景的星系/星球点击、拖拽、滚轮、键盘能力 |
| 左下个人终端 | 自己的星球小预览、当前频道、必要的未读标记 | 靠近个人终端；默认进入上次个人频道，首次进入“我的星球” |
| 中下探索终端 | 简短雷达式预览、探索频道、请求状态 | 靠近探索终端；默认进入上次探索频道，首次进入“撞歌” |
| 右下分类旋钮 | 歌曲 / 艺人 / 曲风三档，明确显示当前档位 | 更改 Galaxy 分类；在 Galaxy 中保留短暂模糊与重排 |
| 航行杆 | 我的星球 ↔ Galaxy；访问中显示返回目的地 | 执行真实目的地切换，不承担普通频道切换 |
| 设置键 | 齿轮与“设置”短标签 | 在探索终端打开设置；返回时还原原终端与原频道 |
| 航向表 | 当前观测方向或巡游位置 | 展示真实场景状态；不是必须操作的入口 |
| 信号表与状态灯 | 就绪 / 搜索 / 航行 / 暂不可用 | 展示真实请求状态，不伪造延迟、百分比或在线人数 |
| 舷窗下沿 | Galaxy 横轴，或具体星系名称及返回控制 | 保留横轴逻辑、画面中心对齐与末端回自己的星球 |

所有关键控件都同时拥有可读名称和语义按钮/输入。用户不需要猜“某个无标签的摇杆”究竟是设置还是漫游。

## 3. 完整功能迁移地图

### 3.1 个人终端

顶部保留三个主要频道键：我的星球、Orbit、Moment。星球资料/歌曲管理和外观编辑是“我的星球”的内部页，不额外堆满驾驶舱硬件。

| 功能 | 新位置和呈现 | 保留的行为与边界 |
| --- | --- | --- |
| 初次创建 | 我的星球 → 创建页；左侧预览随选曲更新，右侧填写 | 创建时选三首歌，名称必填，标语可选，明确显示默认公开及关闭选项；失败保留填写 |
| 我的星球 | 左侧球体预览和当前主旋律；右侧歌曲及简短资料 | 当前音乐版一人一颗星球，不恢复旧情绪版六颗星球 |
| 选歌/换歌 | 我的星球 → 管理歌曲；搜索与选择都在屏幕内 | 创建后三首不是固定上限，继续保留 1–5 首及主旋律选择；示例曲目明确不可播放 |
| 名称/标语 | 我的星球 → 编辑资料 | 保留现有长度限制：名称 40，标语 120；取消不改变已保存值 |
| 外观编辑 | 我的星球 → 外观；左实时预览，右参数组 | 保留四个分类选择器与十五个数值参数、应用/取消/重置、版本冲突提示；换歌保留手动覆盖 |
| 发 Moment | Moment 页右侧原生输入；左侧星球/歌曲预览 | 关联歌曲，正文最多 500 字，逐条公开/仅自己，默认公开；确认保存后才清空草稿 |
| 历史 Moment | 同页下方列表；点开进入终端内详情/编辑页 | 保留编辑、删除、切换可见范围；删除在终端内二次确认，不弹到驾驶舱外 |
| Orbit | 分组页签与联系人列表 | 撞歌遇见、好友、我访问过、访问过我、路过的星球五组全部保留 |
| 好友请求 | Orbit → 请求收件箱 | 发出、接受、拒绝、取消等以实际 API 支持为准；尊重对方关闭申请与屏蔽状态 |
| 私信 | Orbit → 好友 → 对话页 | 只有好友可私信，保留现有 2000 字上限、未读与发送失败反馈；切换频道保留未发送内容 |
| 好友卫星 | 舷窗可点，个人终端可管理 | 真实好友与三位默认虚拟好友明确区分；虚拟好友不伪装为可访问、可私信真人，可移除 |

个人终端近景沿用第二张图的“左预览、右操作”。窄屏将两部分变为同一屏幕内的预览/操作切换，不生成另一个独立弹窗。

### 3.2 探索终端

主要物理频道键为撞歌、漫游、漂流瓶；Galaxy 列表、访客资料、设置等是按场景与操作打开的内部页面。

| 功能 | 新位置和呈现 | 保留的行为与边界 |
| --- | --- | --- |
| 撞歌 | 撞歌频道 → 选歌 → 同歌结果 | 同一标准歌曲 ID 才是撞歌；主动选歌/公开 Moment 的来源可解释。没有结果就空状态，不把相似曲目冒充同歌 |
| 搜索/排名状态 | 屏幕扫描线与真实结果列表 | 保留现有模型排序及规则兜底状态，不声称离线模型已经在线；扫描本身不触发星云 |
| 随机漫游 | 漫游频道 → 推荐 → 换一批/前往 | 相对相关且有随机性；保留真实推荐理由、模型/规则兜底，不新增另一套匹配定义 |
| Galaxy 星系列表 | 舷窗选中星系后，探索终端显示相应列表预览 | 打开屏幕才能近景浏览列表；公开可访问即可前往，不要求同歌 |
| 访问预检 | 终端内目的地页：名字、访问方式、隐身开关、前往/取消 | 默认留痕，隐身选项进入前明确展示；预检本身不写访问记录 |
| 对方星球资料 | 抵达后探索屏幕待命预览；点击再放大查看 | 名称、标语、歌曲、公开 Moment（含已有配图）、好友申请、举报/屏蔽按权限显示；私密内容不可加载或透出 |
| 继续探索 | 对方星球资料中的歌曲/漫游入口 | 先展示结果，再由用户确认下一次访问；不因读资料自动飞走 |
| 漂流瓶首页 | 接收 / 发出 / 传播记录三部分 | 每天最多新发一只，不保证每日收到；歌曲/资讯/公开 Moment 主题不变 |
| 漂流瓶详情 | 屏幕内详情页 | 阅读、评论、点赞、删除自己的评论、举报、作者访问、继续放流都保留；附言与评论继续限制 500 字；阅读和放流不播放星云 |
| 漂流瓶超时 | 信号状态与列表状态同步 | 保留未读一小时后的系统重投及现有调度；不能把本地倒计时当作投递事实 |
| 设置 | 专用设置键进入探索终端 | 星球公开范围、好友申请、收瓶、屏蔽、匿名身份说明、删除账号、显示效果等；星球资料编辑移至个人终端 |
| 审核 | 仅有权限者在设置内部进入 | 举报队列和处置沿用鉴权；普通用户不显示管理入口 |

歌曲的封面、歌名、艺人、演示标记与官方跳转都保留。没有合法播放源就不制造播放器或音频；“音乐卫星”点击先打开对应歌曲信息与可执行的现有操作。

## 4. 视角与交互规则

### 4.1 三种独立状态

整个界面必须拆成三个互相配合但不混为一谈的状态：

1. **外部目的地**：我的星球、Galaxy、正在访问的星球；Galaxy 另有分类、当前星系、巡游位置。
2. **驾驶舱视角**：总览、个人终端近景、探索终端近景；每个终端记忆自己的频道、列表和返回历史。
3. **航行状态**：空闲、起航、穿越/等待、抵达、返回、失败/取消恢复。

例如：外部仍是 Galaxy，用户可以在个人终端写 Moment；关闭屏幕后看到的还是同一星系、同一朝向，而不是突然回自己的星球。

### 4.2 屏幕靠近与返回

- 点击屏幕或其明确频道键，进入相应终端。物理小屏只展示足够的预览，不把完整表单塞进 150 像素高的设备里。
- 靠近时解除侧翼透视，将屏幕变成正视的浏览器内大面积页面，边框仍可见；不调用浏览器原生 Fullscreen API。
- 建议靠近约 550ms、退回约 450ms。动画期间不重复触发；内容默认可用，不依靠动画结束才初始化。
- 保持当前列表滚动、选中曲目、Moment/漂流瓶/私信草稿与外观预览。返回驾驶舱不是“取消编辑”；显式取消才按对应表单规则处理。
- 屏幕固定有“返回驾驶舱”，内部页有“返回”。Esc 先回内部上一层，再退回驾驶舱；输入法组合期间不抢 Esc。
- 设置从任何空闲频道进入，返回还原进入前的终端、频道与滚动位置，不固定回首页。
- 终端放大后锁定窗外拖拽、滚轮与点击；背景继续低频呈现或按性能暂停，不接受穿透输入。
- 返回时将键盘焦点归还触发的物理按钮；隐藏的频道不参与 Tab，也不被屏幕阅读器重复朗读。

### 4.3 旋钮、航行杆、卫星与滚轮

- 分类旋钮提供歌曲/艺人/曲风三个可读档位；支持点击档位和键盘方向键，不要求用户完成拟真的鼠标圆周拖拽。
- 处于 Galaxy 时调档：保留原场景 → 短暂模糊 → 新分类数据就绪 → 重排 → 清晰。请求失败保持旧档位和旧场景并给出重试。
- 不在 Galaxy 时调档只改变准备使用的分类，不自动起航；实际进入 Galaxy 时按该分类加载。
- 航行杆用于“去 Galaxy / 回我的星球 / 返回出发地”，标签随真实目的地更新；航行中不能再次起航。
- 点好友卫星进入 Orbit 中对应项；只有真实可访问星球才提供前往。点音乐卫星打开歌曲信息，不直接认定撞歌发生。
- 总览的舷窗滚轮沿用当前场景规则；Galaxy 末端返回自己的星球。终端、输入和列表中的滚轮只滚动自身。
- 移动端拖动控制台和拖动舷窗分属不同手势区域；不要把同一次触摸同时解释成“移动控制台”和“旋转星系”。

## 5. 星云转场与加载策略

### 5.1 什么时候使用星云

| 操作 | 动效 |
| --- | --- |
| 打开/关闭终端 | 设备靠近/退回，不换目的地 |
| 切频道、读 Moment、收瓶/读瓶、搜索撞歌、换漫游结果 | 屏幕内短扫描/状态反馈，不穿越星云 |
| 我的星球 ↔ Galaxy | 保留现有星云，正向/反向对应 |
| 从撞歌、漫游、Galaxy、Orbit 或漂流瓶确认访问其他星球 | 使用现有星云作为真实航行与数据加载遮罩 |
| 访问后返回出发地 | 反向航行；恢复原目的地及观测状态 |
| Galaxy 分类切换 | 短模糊和重排，不穿越星云 |

### 5.2 一次访问的完整时序

```text
终端结果 → 访问预检 → 确认前往 → 退回驾驶舱
                                   ↓
                           出发地远离 / 星云加深
                                   ↓
                       等待可访问的完整目的地数据
                                   ↓
                     目的地从远处小点逐渐放大 → 抵达
                                   ↓
                    驾驶舱总览 + 探索终端资料预览
```

- 保留现在喜欢的星云材质与运行方式，不替换成视频、GIF、静态 WebGL 截图或通用模糊淡入。
- 正常加载时，星云主段以现有约 2.1 秒作为基准；退回终端属于前置动作。网速慢时延长浓星云段，而不是露出未加载好的半颗星球。
- 目的地数据和外观参数完整后才开始显影。星球从小、远、弱逐渐变大、靠近、清晰；不能在半途插入一个完整静止星球。
- 反向应完成“当前星球缩回远处小点 → 星云穿出 → 出发场景恢复”，不能仅缩小一点就闪切。
- 抵达默认停在驾驶舱总览，不立即强制放大资料终端，让用户先看到到达的星球。
- 用真实状态驱动信号灯：查询中、目的地就绪、航行、失败。未知剩余时间不显示假的百分比。

### 5.3 异步与副作用约束

- 每次航行有独立令牌；同时只允许一个访问确认请求。连点、重复滚轮不能产生多次访问写入。
- 数据返回必须同时匹配航行令牌和账号状态。取消、换账号、失败后的迟到响应不能把画面拉回旧目的地。
- 预检不写入，确认才使用原访问接口；网络中断或取消不能声称服务端访问足迹已撤销。
- 加载失败、星球转私密、被屏蔽、删除等情况：回到出发场景，恢复原终端结果与草稿，并显示具体可理解的原因。
- 请求可取消时取消客户端读取；仍需拦截不可取消 POST 的迟到结果。绝不为重试自动重复提交一个尚不能确认失败的访问写入。
- 首次连接慢/失败时，驾驶舱仍存在；终端显示读取/重试，不能又退回旧扁平错误页面。

## 6. 视觉规范与 dithering 的关系

### 6.1 两套受控色域

- **舷窗宇宙**：沿用紫、粉、蓝与黑白。不得因为设备采用琥珀色，就把外部星球、星云和音乐参数映射整体染黄。
- **舱内硬件**：旧米白/米黄外壳、暖深灰阴影、黑色屏幕、低饱和琥珀字与少量橙色状态灯。金属与塑料变化靠明暗和局部磨损，不增加大面积霓虹彩色。
- 删除现有大面积渐变文字与无意义副标题；正文、输入和隐私提示保持清晰。颜色之外有文字/图标区分状态。

### 6.2 每层怎样使用 dithering

| 层 | 实现要求 |
| --- | --- |
| 星球/卫星/星云 | 继续真实实时抖动材质与现有球面体积；形状和纹理同步旋转，遮挡和拾取保持一致 |
| 硬件外壳 | 参数化灰度/双色抖动用于阴影、斜面和少量磨损，不把所有表面涂成同密度马赛克 |
| 雷达/航向/仪表/频道图标 | 复用阈值纹理、像素轮廓、有限色阶；线条与读数不能被滤镜吞掉 |
| 按钮与状态灯 | 当前选择、按下、禁用和焦点有不同外观；设备形态一致，短标签明确 |
| CRT 屏幕 | 稳定的轻扫描纹、细颗粒和边缘衰减；只是附加质感，不取代 dithering |
| 长文字与表单 | 原生 DOM 文字与输入，常规中文字体；不用噪点过滤正文，保证选择、复制、输入法与辅助技术可用 |

不要把原来的 dithering 球体替换成另一层圆点云；鼠标扰动与默认节拍潮汐仍作用于实际材质块，而不是罩在星球外的装饰层。

### 6.3 硬件细节与 CRT 克制

- 使用一套螺钉、边框、通风槽、刻度、开关与指示灯；相同部件跨屏复用，避免每个频道另造美术语言。
- 外壳有少量局部划痕、明暗层次和凹入屏幕，不使用整屏高强度脏污遮住内容。
- 仪表指针平缓变化，显示真实航向和信号状态；不存在的数据不用随机假数字填满。
- CRT 静态纹理保持很轻；切频道可以短暂重扫，偶发跟踪偏移幅度极小，不黑屏、不出现虚假故障、不让整段文字持续抖动。
- 输入中暂停跟踪偏移；设置提供显示效果开关并在本机保存。减少动态效果关闭所有非必要闪动和长靠近/航行动作。
- 正文对比度至少 4.5:1、大文字至少 3:1；长文不依赖光晕提高可读性。焦点环始终清晰。

## 7. 状态、反馈与草稿持久性

| 状态 | 呈现 | 可执行操作 |
| --- | --- | --- |
| 初次进入、身份读取中 | 驾驶舱已显示，个人终端连接中 | 不展示旧导航页；不触发重建身份 |
| 无星球 | 舷窗既有创建预览，个人终端“创建星球” | 选曲、起名、设置公开范围；保留现有探索权限 |
| 正常总览 | 两终端小预览与真实状态灯 | 打开终端、观察、分类、航行 |
| 终端近景 | 当前频道占据屏幕，其他世界操作锁定 | 表单/列表/返回/设置 |
| 无撞歌结果 | 一句空状态与换歌入口 | 不生成假人、不自动降为相似歌 |
| 漫游/瓶收件为空 | 可理解的空状态 | 换一批、发瓶或返回，不承诺一定收到 |
| 请求失败 | 保留旧列表，屏幕内错误与重试 | 不清空已完成内容，不强制退出设备 |
| 保存成功 | 屏幕内短状态反馈 | 更新实际数据后显示成功，不仅播放动画 |
| 保存失败/外观冲突 | 草稿与预览仍在 | 重试、重新读取已保存版本、显式取消 |
| 航行等待 | 浓星云与真实请求状态 | 防重入；等待或取消/返回 |
| 对方不可访问 | 恢复出发画面和结果 | 知道失败原因，继续选择其他对象 |
| WebGL 不可用 | 非空 Canvas 降级与可访问列表 | 全部业务继续可用，不无限等待图形加载 |
| 匿名身份重置/删除 | 确认完成后清除旧账号缓存 | 不将旧私信、私人 Moment、草稿带给新身份 |

草稿包括创建表单、资料修改、选曲、Moment、私信、漂流瓶和外观编辑；返回/切频道保留会话内状态。删除账号/身份切换必须清除账号相关草稿。跨刷新私密草稿保存不是本次默认新增能力，避免直接把私人内容放进无保护的长期浏览器存储。

列表滚动位置按终端和页面保存；隐藏页面暂停额外轮询和动效。保留状态不等于让所有页面永久在后台请求。

## 8. 技术改造设计

### 8.1 分层与文件拆分

建议在当前音乐目录内增量拆分，不重写所有服务端功能：

```text
src/music/
  MusicApp.tsx                身份与业务数据协调、API 接入
  cockpit/
    CockpitShell.tsx           外壳、舷窗、设备布局与终端靠近
    cockpit.css               舱内专属 tokens 与响应式
    state.ts                  目的地 / 终端 / 航行状态
    controls/                 旋钮、航行杆、仪表、指示灯
    terminals/                个人与探索终端、内部导航
    pages/                    各业务页，逐步从 MusicApp 抽出
    travel.ts                 航行时序、令牌和加载交接
  dither/
    Stage.tsx                 现有世界；接收独立目的地与交互锁
    DitherCanvas.tsx           单主渲染器生命周期
    stage-layout.ts           视口内布局、遮挡与转场采样
    renderer.ts / shaders.ts  保留已有实时抖动管线
```

文件名为建议施工结构。先迁移呈现，再拆分业务；不为了目录整齐而一次重写所有请求处理。

复用部件至少包括：设备边框、屏幕表面、频道键、机械按钮、三档旋钮、航向/信号仪表、状态灯、内层滚动区、空状态与错误反馈。

### 8.2 世界与界面解耦

当前 `MusicApp.tsx` 同时管理页面、场景和访问状态，`Stage` 也曾用业务页面判断是否显示 Galaxy。改造必须解除这类关系：

- 打开 Orbit、设置、漂流瓶不能通过同一个 `view` 隐式改变目的地或清除当前访客。
- 页面导航管理界面历史，航行管理目的地历史；返回按钮明确属于哪一种。
- 保留现有账号级迟到响应检查，再加航行/分类请求级的“最后一次有效请求”保护。
- 一个状态源决定当前外部场景；不要让 CSS、页面条件和异步响应各自决定场景。

### 8.3 单渲染器与正确拾取

- 全程保留一个主 WebGL2 上下文，靠近、退回和切频道不卸载重建主 Canvas，也不反复创建 shader。
- 舷窗容器用 `ResizeObserver` 更新实际边界和 DPR；缩放或透视变化后用真实矩形转换鼠标坐标。
- 场景布局以舷窗内部尺寸计算，不再假定整个浏览器都是宇宙区域。导航轴独立固定在舷窗中心，不随世界横向平移。
- 近景中的个人星球预览复用同一外观参数；用共享渲染输出/轻量 Canvas 预览，不为每个屏幕、列表行另开 WebGL。
- 保存各资产的旋转与材质运动状态，场景隐藏/显现或预览尺寸变化不应每次从零开始。
- 隐藏页面暂停 RAF；焦点终端的背景降频/暂停；缩略图缓存有上限，账号变化清除私人缓存。
- Canvas2D 是明确降级路径，可减少动态表现，但必须保留非空星球、前后遮挡和可访问业务入口。

### 8.4 数据与权限

- 私人 Moment、私信、屏蔽对象不可因为设备预览/缩略图缓存而泄露给访客。
- 公共列表可短期复用缓存；实际前往仍必须由访问接口重新校验公开和屏蔽状态，不能凭缓存绕过权限。
- 视觉与音乐仍采用现有确定性参数映射；没有真实音源时，80 BPM 仍是预览频率，不能标成当前歌的测量结果。
- 设置、好友、瓶、Moment 等保存只在明确业务动作时发生；靠近设备和查看列表不得制造新增记录。

## 9. 响应式、键盘与性能

### 9.1 桌面与移动

| 环境 | 总览 | 终端近景 |
| --- | --- | --- |
| 大桌面 | 完整 U 形控制台，大舷窗 | 设备正视展开；个人页预览/操作两列，探索页依数据密度分栏 |
| 小笔记本/平板横屏 | 收紧壳体边缘和仪表间距，不先缩正文 | 终端适配可用宽高，各列表内部滚动 |
| 手机横屏 | 保留驾驶舱横向空间关系 | 边框简化但设备感保留，操作仍可触摸 |
| 手机竖屏 | 舷窗保持完整宽度；下方控制台允许局部有界横向移动，有可见切区提示 | 整个终端适配屏宽，预览/操作页内切换，不强制用户横屏 |

控制台局部横向移动不等于页面整体横向溢出。页面 `scrollWidth` 应等于视口宽度；屏幕正文只纵向滚动。使用动态视口高度与安全区，软键盘出现时输入框和提交按钮可见。

### 9.2 输入与无障碍

- 主要触摸目标至少 44×44 CSS 像素；没有 hover 也能理解和操作。
- 键盘可打开两终端、调分类、返回、访问可达场景对象；方向键只在对应区域有焦点时作用。
- 浏览器后退映射为终端内部返回或航行返回，不意外关闭应用；恢复状态不重新执行 POST。
- 近景焦点局限在当前终端，退回后恢复入口焦点；状态变化使用适量的可访问通知，不连续朗读每帧航向。
- 系统减少动态效果使用短淡入或即时切换；设置中的 CRT 开关不关闭核心可读功能。

### 9.3 性能目标

- 不新增大型图像背景、视频、模型资源；以代码和小型纹理实现硬件。
- 主机桌面目标维持当前可用流畅度；用同一设备、同一场景比较改造前后，而非宣称所有设备恒定 60fps。
- 保留现有自动降质和像素块总量上限，避免界面动效与材质物理同时无限加量。
- 至少记录桌面/手机的帧时间、资源体积、WebGL 上下文数及开关终端后的稳定性；质量下降应逐级，不能突然变成另一种美术。

## 10. 分阶段实施与完成门槛

阶段是组织施工的方式，不是只交付前三页就停止的“最小闭环”。完成标准是下列全部范围迁移、验证与发布。

| 阶段 | 任务 | 阶段交付与通过条件 |
| --- | --- | --- |
| 0. 基线与隔离 | 固定当前可用音乐分支/提交，记录业务与视觉基线，核对 staging 绑定 | 本地/远端/线上状态分开记录；重资产不提交，旧站点和旧 D1 不在发布目标中 |
| 1. 导航契约 | 建立目的地、终端、频道和航行状态，保存返回上下文 | 打开任何频道不改变窗外；迟到响应、返回历史、重置身份有测试 |
| 2. 驾驶舱骨架 | U 形外壳、两屏、旋钮、杆、仪表、横轴；两终端近景/退回 | 全部入口可点击可键盘；页面不依赖背景插画；先人工核对整体包围感 |
| 3. 个人功能迁移 | 创建、选歌/资料、外观、Moment、Orbit、好友与私信 | 草稿、失败、取消、冲突、隐私和五分组全部保留；外观不再独立弹窗 |
| 4. 探索功能迁移 | 撞歌、漫游、Galaxy 列表、瓶、访客、设置与审核 | 所有业务在终端内部完成；确认、举报和危险动作有屏幕内明确流程 |
| 5. 航行与渲染交接 | 统一星云加载/返回、慢网保持、拒绝迟到结果、真实视口布局与拾取 | 各来源访问同一套航行；首次到达无空白/突然弹出，返回完整反向 |
| 6. 视觉与移动硬化 | 抖动硬件、轻 CRT、真实仪表、窄屏、软键盘、降低动态与降级 | 桌面与手机实测截图；所有输入区域隔离，无文档级横向溢出 |
| 7. 全量验收与发布 | 完整测试、构建、staging 检查、实际双身份业务验证、代码推送与发布 | 发布隔离音乐 staging 的 `main` 环境，核对线上资源与读写，保留可回退版本 |

功能迁移每批先写/更新对应行为回归，再调整呈现。既有业务测试不是为新布局全部删除；更改过时的 DOM/入口预期，保留权限、状态和数据断言。

只向已明确授权的音乐改造分支提交代码。Cloudflare Pages 的 `main` 发布环境不等于 GitHub 旧情绪版 `main`；不要误合并旧分支或使用旧生产 D1。

## 12. 风险、裁定与最终交付

| 风险 | 处理方式 |
| --- | --- |
| 模仿插画导致操作区过小 | 小屏只做预览与入口，真正任务在正视近景完成；优先可读与可点击 |
| 一个页面状态同时控制所有东西 | 先解耦目的地/终端/航行，再迁移 JSX，避免在旧条件上叠新动画 |
| 倾斜/缩放造成点不中 | 实际边界重新计算；设备按钮用原生 DOM，星球保留显示与拾取一致的管线 |
| 靠近终端重建世界、星球加载闪现 | 持续主渲染器、参数与状态缓存、数据就绪后显影、慢网停留浓星云 |
| CRT 与 dithering 叠加使中文字难读 | 图形层抖动，正文原生；静态纹理克制、输入时暂停动态、支持关闭 |
| 假加载/假仪表削弱产品可信度 | 只展示真实状态，无测量来源不展示数字；示例歌不可播放的说明保留 |
| 隐藏页面保留了草稿却持续发请求 | 状态与挂载/活动分开管理；隐藏时暂停轮询、动画，身份切换清缓存 |
| 把历史六星球/天气混进音乐改造 | 以当前音乐规则为基线；本轮只重构呈现与导航，不扩大旧业务范围 |

本方案已给出可执行默认方向；比例、透视角度与动效时长是初始标定值，允许实际实现时微调，但不得改变包围式布局、终端物理入口、dithering、星云保留和业务完整性。

实际实施完成时应交付：可运行的全量驾驶舱界面、可复用硬件组件、音乐入口专属设计规范、更新后的行为测试、桌面/移动与转场验收证据、明确的 Git 提交和隔离 staging 发布/回退信息。未达到这些条件不能把骨架或截图称为完整改造。

规划方法：使用 `frontend-design` 的 `shape` 流程，将已确认参考转化为布局、交互、状态、可读性与验收规格；用户已明确取消新增参考图，因此本轮不再进行视觉探针或图片生成。
