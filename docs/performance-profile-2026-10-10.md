# 星球像素降档：性能采样与改善建议

日期：2026-10-10。下方原始报告记录诊断时的状态；用户随后批准实施，实施与发布证据见文末追加记录。

## 结论

不是单一问题，而是 CPU 逐格运动计算、GPU 超范围星云绘制、驾驶舱滤镜/合成三者叠加。保留星球像素细度是合理方向，但只禁止自动降档并不能解决卡顿。

## 测量方法和边界

- 从正式站只读取得当前匿名账户的星球外观、音乐卫星、好友卫星配置，使用当前源码的真实 `DitherCanvas`、运动、WebGL 渲染器和 `CockpitShell` 搭建临时本地采样页。
- 场景可视区域约 1418 × 568 CSS px，设备 DPR 为 2；正常渲染上限 DPR 为 1.5。2 倍宽高的 overscan 使实际画布达到 4254 × 1703，面积是同等 DPR 可见画布的约 4 倍。
- 关闭本地采样页的自动降档，固定完整细像素场景约 **62,366 格**；各对照保持相同格数。线上进场动画会通过粒子网格复用保留较小的格数，上一次实测为 42,813，因此下列数据是受控细像素负载，不是线上每次进入都必然发生的耗时。
- 每种情况先预热 1.5 秒，再采样 4.5–5 秒；做了多个基线。记录 CPU 分段计时、实际绘制回调频率，以及 `EXT_disjoint_timer_query_webgl2` GPU 查询结果。
- GPU 时间采用中位数；CPU 表中的时间采用每帧均值。CPU/GPU 可以并行，**不能相加得到整帧时间**。GPU 查询不涵盖完整浏览器页面合成，也不能当作整机 GPU 占用率。
- 没有取得全浏览器 CPU 火焰图：独立采样连接未返回，已终止。结论依据帧级分段计时和受控 A/B，不冒充全进程性能跟踪。
- 本地组件使用开发构建，驾驶舱内容为简化占位；没有完整业务数据流和音频解码。数字用于热点定位与相对比较，不能作为正式发布帧率承诺。

## 实测结果

| 项目 | 实测 | 判断 |
| --- | --- | --- |
| 完整细像素基线 | 约 24–28 FPS；运动 CPU 约 24–26ms/帧 | 超过 60 FPS 的 16.7ms 单帧预算 |
| 像素运动与积分 | 代表性基线约 18.1ms/帧 | 大量重复潮汐公式、三角函数、幂运算及逐格弹簧积分 |
| 黑缝覆盖修复 | 同一基线约 7.2ms/帧 | 每个运动格检查 8 个邻格；这是后来加入的实质开销，不能忽略 |
| JS 提交 WebGL 绘制 | 约 0.6–0.9ms/帧 | 单看 draw 调用耗时会漏掉异步 GPU 开销 |
| 星云背景 | 关闭背景的诊断对照使 GPU 中位数约 15.0 → 4.1ms，CPU 基本不变 | 全屏动态星云是 GPU 大头；不代表正式方案应删除星云 |
| 超范围绘制 | overscan 2 → 1 时 GPU 中位数约 15.0 → 5.3ms，格数不变 | 绘制屏幕外内容有显著成本；直接改成 1 会影响缩放/平移余量 |
| 驾驶舱滤镜 | 保持场景和格数，仅临时禁用滤镜，约 24.4 → 32.1 FPS | 滤镜/栅格化/合成有明显开销；不能把它误计为像素运动独有问题 |
| 深度预绘制 | 临时跳过后未获得明显整体收益 | 不是第一优先级；删除还会破坏遮挡语义 |

注意：更慢的帧还会让物理积分执行更多子步，形成恶性循环——帧间隔变长、每帧补算更多、进一步变慢。当前上限为 50ms、步长 1/120 秒。

## 不减少像素的诊断原型

1. **提取公共计算、以乘法改写整数幂**：运动 CPU 同组对照约 26.4 → 21.4ms。没有减少格数，也没有关掉潮汐。仍有优化空间，不能据此承诺 60 FPS。
2. **邻边去重原型**：配合上述改写，运动 CPU 一组约 25.5 → 18.9ms，约 25 → 30 FPS；但补缝分段本身仍约 7ms，去重尚未证明稳定的独立收益，不建议直接照搬这个原型。
3. **按当前可见区域裁剪 GPU 绘制**：在同样保留 overscan 和格数的情况下，GPU 中位数约 14.4 → 7.3ms。冻结同一画面比较 1,812,204 个可见像素，RGBA 差异为 0，WebGL 错误为 0。原型仅验证居中默认视野；正式实现需正确处理缩放、拖拽、边界和过渡。
4. 数值对照覆盖 3 个旋转角、各 40 个时间步及指针扰动：两种运动实现位置差为 0，格子尺寸最大差约 0.000000954 CSS px。此检查不替代完整交互和补缝回归。

裁剪降低了 GPU 耗时，但组合原型并未稳定提高整体帧率，说明其他瓶颈仍在。不能把各项单独收益直接相加。

## 推荐实施顺序

### 第一批：不改变主星像素和视觉设计

- 优化运动热循环：把每格重复的公共参数移到每帧/每颗星球计算；缓存不变的空间参数；评估缓存潮汐空间相位，保留交互与节拍响应。
- 优化补缝：预计算邻接关系、减少重复寻址；保持黑缝覆盖和鼠标开洞语义。不要为性能直接撤掉补缝。
- 渲染可见区域，而不是每帧重算全部 overscan；背景星云可独立缓存、降低更新频率或在独立较小纹理上生成，主星像素网格保持不变。
- 驾驶舱把静态金属/文字的复杂滤镜结果缓存或预渲染，隔离噪声和扫描线的刷新范围，避免小动画带动大区域重新栅格化。

### 第二批：改良降级策略

- 主星像素粒度作为外观属性，优先保持稳定；性能策略与用户设定的像素粒度分离。
- 优先减少背景刷新、装饰动画、远处对象工作量，再考虑降低物理更新频率并插值；这类取舍仍需用实际画面对照验证。
- 只按整体 RAF 间隔计数容易将页面合成、加载和其他主线程任务造成的慢帧算到星球头上。应结合实际工作耗时、启动宽限期、持续窗口和恢复机制，避免一次降档后永久锁低。
- 若前述优化后仍受 CPU 限制，再评估 Worker 或 GPU 运动计算；不建议第一步就大规模重构或硬锁高画质。

验收优先看正常进入、音乐播放、鼠标扰动、访问/返航、缩放平移的帧时间 P95，以及像素格数是否稳定；同时回归黑缝和遮挡。先在完整生产构建中复测，再部署，不能把本报告中的诊断原型当成已上线修复。

## 经批准实施：保留像素细度

### 已实现

1. 运动计算缓存每个活动网格的旋转坐标和空间波相位；时间相位、力度只按星球/帧计算。以乘法计算整数幂，避免逐格重复三角函数。网格替换可回收缓存，旋转变化时重算；脉动、音乐节拍与指针互动仍实时生效。
2. 保留 8 邻格补缝及其覆盖上限。邻边去重原型没有证明独立收益，未引入风险性替换。
3. 根据实际 CSS 缩放/平移反算可见矩形，WebGL 使用向外取整的 scissor。保留 overscan、坐标体系、DPR 和格数；每次裁剪前清除完整旧颜色/深度，避免平移后旧画面残留。
4. 咖啡蒸汽独立为与桌面同坐标系的 SVG，只在小范围蒸汽组保留硬件滤镜，不再作为大型静态桌面滤镜的动画子节点。未删除金属/文字抖色效果。
5. 自动模式不再降低格数或 DPR。启动宽限 2 秒，持续超载约 2 秒后将目标动画更新从 60Hz 调到 30Hz；自身计算与原生 RAF 持续约 6 秒有余量才恢复。暂停/隐藏切换重置采样，显式 low 模式仍可使用。此策略保留像素细度，但不能保证所有设备达到目标帧率。

### 验证与当前收益

- 11 个相关测试文件 **63 项通过**；生产构建 TypeScript + Vite 通过。未运行完整测试集。
- 测试先证实旧实现违反空间缓存、独立绘制根节点、可见矩形和持续慢帧保持粒度的约束，再实现修复。同步更新了旧桌面测试的蒸汽父节点断言；还修复了 reduced-motion 属性变化时重新绘制使用陈旧状态的问题。
- 原生浏览器，3 个旋转角各 40 步并含指针扰动：原始潮汐公式与缓存公式的最终位置/补缝尺寸最大差均为 **0**。
- 真实 WebGL 冻结同一帧比较默认、0.5 倍缩小、2 倍放大平移、边界平移。分别检查 1,575,000 / 6,300,000 / 393,750 / 1,575,000 个可见像素，RGBA 通道差异均为 **0**，WebGL 错误为 0。
- 同一前台本地采样页，固定 60Hz 目标（不强迫实际达到），各预热 1.5 秒、采样 4 秒，均保留 **62,366 格**及 4254 × 1703 画布。基线运动 CPU 34.88ms → 全部优化 21.73ms；GPU 中位数 13.81ms → 7.75ms；实际约 20.0 → 23.1 FPS。机器负载与前一轮诊断不同，不能与原报告直接拼接比较。
- 逐步结果：只做运动缓存 CPU 23.42ms；增加裁剪 GPU 16.51 → 6.77ms。桌面分层在这轮未显示稳定的独立帧率收益（23.6 → 23.1），不宣称这一项已提升 FPS。
- 以上为开发构建/简化业务界面的受控对照，不是完整正式站帧率承诺。测试页节拍为受控 63 BPM，不代表播放器正在解码。截图与对比保持真实前台 RAF，没有伪造可见性。
- 第一轮 A/B 的固定频率开关只停止采样但继承了之前 30Hz 状态，因此没有拿它充当 60Hz 对比。修正测试页开关后重新测量，正式结果为 `/tmp/mosic-preserve-ab-final.json`；数值/像素证据为 `/tmp/mosic-preserve-validation.json`。
